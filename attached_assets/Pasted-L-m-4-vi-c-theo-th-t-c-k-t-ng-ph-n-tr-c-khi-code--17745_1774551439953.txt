PHẦN 1 — XÓA SPRINT KHỎI TOÀN BỘ HỆ THỐNG
═══════════════════════════════════════════════════════

Bỏ hoàn toàn khái niệm Sprint trong FlowOS.
Thay thế bằng timeline thực tế (ngày bắt đầu / kết thúc).

1. Prisma schema — model GiaiDoan (Sprint):
   Xóa bảng GiaiDoan khỏi schema
   Xóa field giaiDoanId khỏi model CongViec
   Chạy: npx prisma migrate dev --name remove_sprint

2. Tất cả API — xóa params liên quan sprint:
   GET /api/cong-viec: bỏ param sprintId
   Thêm params: tuTuan, denNgay (date range filter)

3. Frontend — xóa mọi chỗ hiện "Sprint X":
   Tìm toàn bộ file tsx/ts có chữ "sprint" hoặc "Sprint"
   Thay bằng khoảng thời gian: "28/03 → 04/04"
   Hoặc hiện ngày kết thúc: "Hạn 04/04"

4. Import Excel (nhap-du-lieu.ts):
   Bỏ đọc sheet "⏰Sprint"
   Không import GiaiDoan nữa

PHẦN 2 — RULE MỚI: CÔNG VIỆC NHẬP THEO BƯỚC
═══════════════════════════════════════════════════════

Rule mới (thay thế rule OKR cũ hoàn toàn):

NGUYÊN TẮC:
  - Công việc KHÔNG còn nhóm theo OKR/Mục tiêu
  - Công việc NHÓM THEO BƯỚC (NAP3, RD4, BBC1...)
  - Leader hoặc nhân sự tự nhập công việc vào bước
    của mình trực tiếp trong FlowOS
  - Mỗi bước có thể có nhiều công việc con
  - Bước XONG khi TẤT CẢ công việc trong bước XONG
    HOẶC leader đánh dấu bước xong thủ công

CẤU TRÚC DỮ LIỆU mới của CongViec:
  Bắt buộc:
    ten          - tên công việc (nhập tự do)
    buocId       - thuộc bước nào (bắt buộc)
    inchargeId   - người phụ trách (bắt buộc)
    ngayKetThuc  - hạn hoàn thành (bắt buộc)
  
  Tự động điền từ bước:
    duAnId       - lấy từ buoc.duAnId
    sanPhamIds   - lấy từ buoc.sanPhamIds
  
  Không bắt buộc:
    ngayBatDau   - ngày bắt đầu
    moTa         - mô tả chi tiết
    dinhNghiaHoanThanh - khi nào coi là xong
    nguoiPhoiHop - người phối hợp (array)
    uuTien       - Cao / Trung bình / Thấp
    ghiChu       - ghi chú tự do
  
  Xóa hoàn toàn:
    mucTieu (OKR field) - không dùng nữa
    giaiDoanId (Sprint) - không dùng nữa

LOGIC TRẠNG THÁI BƯỚC tự động:
  Bước = CHUA_LAM  khi 0 công việc DANG_LAM/XONG
  Bước = DANG_LAM  khi có ít nhất 1 CV DANG_LAM
  Bước = BI_CHAN    khi có CV BI_CHAN (ghi đè trên)
  Bước = XONG      khi tất cả CV XONG
                   HOẶC leader bấm "Đánh dấu xong"
  
  Cập nhật realtime qua WebSocket sau mỗi lần
  đổi trạng thái công việc.

THÊM API:
  POST /api/buoc/:id/cong-viec
    Body: { ten, inchargeId, ngayKetThuc,
            ngayBatDau?, moTa?, uuTien? }
    Tự điền duAnId, sanPhamIds từ bước
    Trả về: CongViec mới tạo

  PATCH /api/buoc/:id/danh-dau-xong
    Leader đánh dấu bước xong thủ công
    Đổi trangThai = XONG bất kể CV con

PHẦN 3 — HỆ THỐNG DEPENDENCY VÀ TIMELINE IMPACT
═══════════════════════════════════════════════════════

Xây dựng hệ thống phụ thuộc và tác động timeline.

--- SCHEMA ---

Thêm vào schema.prisma:

model PhuThuocCongViec {
  id            String   @id @default(cuid())
  congViecId    String
  phuThuocVaoId String
  loai          String   @default("FINISH_TO_START")
  soNgayBuffer  Int      @default(0)
  congViec      CongViec @relation("downstream",
                  fields:[congViecId])
  phuThuocVao   CongViec @relation("upstream",
                  fields:[phuThuocVaoId])
}

Thêm vào CongViec:
  upstream    PhuThuocCongViec[] @relation("downstream")
  downstream  PhuThuocCongViec[] @relation("upstream")
  ngayKetThucThucTe DateTime?

Chạy: npx prisma migrate dev --name add_dependency

--- SERVICE ---
File: server/src/services/dependency.service.ts

1. layUpstream(congViecId):
   Đệ quy lấy tất cả upstream
   Trả về: { direct[], indirect[], coUpstreamTre: boolean }

2. layDownstream(congViecId):
   Đệ quy lấy tất cả downstream
   Với mỗi item tính:
     soNgayBiAnh = soNgayTre của task hiện tại
     ngayKTMoi   = ngayKetThuc + soNgayBiAnh
   Trả về: { direct[], indirect[], cotMocBiAnh[] }

3. tinhImpactTimeline(congViecId, ngayKTMoi):
   soNgayTre = ngayKTMoi - ngayKetThucGoc
   Đệ quy cập nhật tất cả downstream
   Kiểm tra ảnh hưởng Launch 15/05 và 15/06
   Trả về:
   {
     danhSachAnh: [{ congViecId, ngayKTGoc,
                     ngayKTMoi, soNgayLui }],
     launchHTBiAnh: boolean,
     launchTTBiAnh: boolean,
     soNgayLuiHT: number,
     soNgayLuiTT: number
   }

4. guiThongBaoDownstream(congViecId, impact):
   Gửi Lark DM cho incharge của mỗi downstream
   Template:
   "⚠️ [Tên task] bị trễ [N ngày]
   → Task của bạn: [tên task downstream]
   Hạn cũ: [ngày] → Hạn mới: [ngày]
   [Xem chi tiết] → link FlowOS"
   
   Nếu launchHTBiAnh → gửi thêm vào nhóm SOS:
   "🚀 Nguy cơ Launch HT 15/05 lùi ~N ngày
   Nguyên nhân: [task] trễ [N ngày]"

--- API ---

GET /api/cong-viec/:id/dependency
Trả về:
{
  congViec,
  upstream:   { direct[], indirect[] },
  downstream: { direct[], indirect[] },
  soNgayTreHienTai: number,
  cotMocBiAnh: []
}

POST /api/cong-viec/:id/cap-nhat-timeline
Body: { ngayKetThucMoi, lyDo }
Bước 1: Cập nhật ngayKetThucThucTe
Bước 2: Gọi tinhImpactTimeline
Bước 3: Trả về impact để user confirm
KHÔNG tự động cập nhật downstream
        (chờ confirm từ user)

POST /api/cong-viec/:id/confirm-impact
Body: { danhSachAnh[], guiThongBao: boolean }
Bước 1: Batch update ngayKetThucThucTe
         cho tất cả downstream
Bước 2: Nếu guiThongBao → gửi Lark DM
Bước 3: Nếu launch bị ảnh hưởng → gửi SOS

POST /api/cong-viec/:id/them-phu-thuoc
Body: { phuThuocVaoId, loai?, soNgayBuffer? }
Tạo quan hệ phụ thuộc giữa 2 công việc

DELETE /api/cong-viec/:id/xoa-phu-thuoc/:depId
Xóa quan hệ phụ thuộc

POST /api/cong-viec/:id/notify-downstream
Gửi Lark DM ngay cho tất cả downstream
